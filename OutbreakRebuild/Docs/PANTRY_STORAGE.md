# Foundation 23: pantry storage

Fed, uninfected humans settled inside a shelter put spare carried meals onto an adjacent shelf in that same room. They keep one meal. Helping an adjacent hungry person takes priority; visible zombies, recent warnings or door impacts, freezing and active fear reactions prevent storage.

A deposit uses one normal action, exposes the shelf's stock and updates the donor's personal notebook. Food is transferred, never created; shelves hold at most 1,000 meals. Other humans can search the shelf through the existing food system. Humans currently stock shelves they stand beside; choosing and walking to a pantry is a later step.

Choose **Inspect Pantry Storage Paused**. Human #1 starts carrying three meals beside an empty shelf. Step one tick: the shelf gains two meals and the human keeps one. Select the shelf to inspect its stock.

New encounters use encounter-prototype-22. Existing saves retain their previous behavior until **Enable pantry storage** (or the upgrade button for older generations) is clicked. The older foraging diagnostic stays on prototype-21 so it continues isolating eating and supply trips.

Core checks exercise conservation, reserve retention, shelf capacity, hunger/infection exclusions, old-generation behavior and exact saved continuation. Unity API doubles compile and exercise production UI handlers; native Unity rendering and Windows input still require local testing.

Validation: 188 core cases / 34,933 assertions; 481 UI assertions in legacy input mode and 3 in NewOnly mode. Project configuration and whitespace checks passed.
