# Foundation 113 — generated city setup

From the main menu choose **Set Up Generated City**. Choose a preset or edit:

- **City seed:** a whole number from 1 to 4294967295. Identical seed and block counts reproduce the initial city.
- **Blocks across / down:** independently choose 2–6. Rectangular maps are supported.
- **Start city paused:** defaults to Yes. Run or step after creation; choose No to start running immediately.

Presets are Small (2×2 blocks), Standard (4×2) and Large (6×6). The form shows exact generated dimensions in cells, buildings, homes, stores, population and food before starting. This summary measures the seeded street axes without generating a terrain map or spawning actors during GUI rendering. Invalid text, zero/overflowed seeds, fractional numbers and unsupported sizes disable Start and display an explanation.

Click **Start generated city**. If a run is already retained, the existing Replace run / Keep current run flow protects it. Editing the form or returning to the menu does not regenerate or change that run. Settings persist during the session independently of encounter-setup settings. The city opens with an overview camera; existing Zoom + / Zoom - and navigation controls let you inspect a neighborhood.

The city uses the Foundation 112 generator: one building per block, seeded footprint sizes/positions, south-facing entrances and paths connecting to preserved sidewalks/crosswalks. There is one distribution center, one store on cities of four or six blocks, and two stores on larger supported cities. Remaining buildings are homes.

Population remains deliberately simple: one human per home, one courier, one clerk per store, and the remaining humans as consumers. Workers start at work, have separate assigned homes and use 07–19 shifts. Thus a 2×2 city has two homes, one store, one center and two workers; it has no pure consumers initially. The standard city keeps the previous five humans/eight buildings/63 meals. The largest city has 36 buildings, 33 homes/humans, two stores and 147 starting meals. Density, family sizes and role ratios are not editable yet.

Starting food remains finite: 40 center meals, four per store shelf, two per home and one carried ration per human. Store crates begin empty; clerks phone for existing courier replenishment. No zombies or ground weapons are generated by this form. Use existing **Place zombie** after starting to introduce an outbreak. Existing encounter setup and diagnostic previews remain available separately.

Restart restores the initial generated world, assignments, food and tick zero; it does not use subsequently edited form values or regenerate supplies during an active run. Saves contain actual terrain, inventory and job state. Loading a save does not populate the separate setup form from that save. Simulation rules remain encounter-prototype-89; no upgrade or migration is needed.

Checks cover invalid/boundary settings, summary accuracy across minimum/maximum/rectangular layouts and seeds including uint.MaxValue, deterministic regeneration, unique homes and staffed workplaces, finite food, save continuation, form parsing, presets, paused/running starts, replacement cancellation/confirmation, restart and the existing encounter UI. Native Unity 6000.6.3f1 layout, input and large-city performance remain unverified; the Foundation 82 checkpoint is unchanged.

Future item categories remain **supplies**, **medical**, **ammo**. Existing food-only storage remains unchanged in this increment.

Foundation 114 updates new generation with [four-way street-facing entrances and building sizes by use](CITY_BUILDING_VARIETY.md). Existing setup controls/counts remain; new cities use updated geometry for the same seed. Saved cities keep their actual layouts.
